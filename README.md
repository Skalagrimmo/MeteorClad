# MeteorClad

Top-down arena action roguelite prototype на **Lua + LÖVE2D**. Поточна кодова база має модульну архітектуру з єдиним контекстом залежностей `ctx`.

## Керування

- **WASD / Стрілки** — рух
- **ЛКМ** — удар мечем і відбиття ворожих снарядів у секторі атаки
- **ПКМ** — Вихровий удар: кругова атака та відбиття снарядів
- **Space** — ривок (Dash) із короткими кадрами невразливості
- **1 / 2 / 3** або **ЛКМ** — вибір покращення при підвищенні рівня
- **R** — перезапуск після поразки
- **F7** — VectorLab: векторне порівняння руху ворогів (повторне натискання вимикає)
- **F8** — радіальне stress-поле; **1 / 2 / 3** — 100 / 500 / 1000 векторів; **Esc** або F8 — вихід

## Запуск

Потрібен встановлений [LÖVE2D](https://love2d.org/).

На Windows можна запустити `run.bat`. Скрипт очікує LÖVE2D за шляхом `C:\Program Files\LOVE\love.exe`.

Альтернативно відкрийте термінал у корені проєкту та виконайте:

```bash
love .
```

## Український шрифт

Для правильного відображення української кирилиці гра використовує Noto Sans Regular.

1. Завантажте [NotoSans-Regular.ttf з офіційного проєкту Noto](https://notofonts.github.io/latin-greek-cyrillic/fonts/NotoSans/hinted/ttf/NotoSans-Regular.ttf).
2. Збережіть файл у цьому репозиторії за шляхом `fonts/NotoSans-Regular.ttf`.
3. Ліцензія SIL Open Font License 1.1 та авторське повідомлення містяться у `fonts/OFL.txt`.

Якщо TTF-файл відсутній або не завантажується, гра не завершується аварійно: LÖVE використовує стандартний шрифт і виводить підказку в консоль. У стандартного шрифту старих версій LÖVE може не бути українських гліфів, тому для читабельної української локалізації додайте Noto Sans.

## Структура проєкту

- `main.lua` — точка входу, створення контексту та callbacks LÖVE
- `config.lua` — параметри арени й типів ворогів
- `utils.lua` — спільні математичні утиліти
- `player.lua` — гравець, рух, атаки та Dash
- `enemies.lua` — створення ворогів, AI, шкода та смерть
- `projectiles.lua` — снаряди, зіткнення та відбиття
- `loot.lua` — XP-сфери та їх підбирання
- `upgrades.lua` — пул звичайних покращень із максимальними рангами
- `masteries.lua` — повторювані бонуси майстерності ветерана після максимального рангу всіх звичайних перків
- `game.lua` — стани гри, хвилі, level-up та введення
- `ui.lua` — HUD, картки покращень і Game Over
- `benchmark.lua` — панель Stage F benchmark і Stage G system profiler (F6)
- `vector_lab.lua` — необов'язкова діагностика руху й радіальне stress-поле (F7/F8)
- `benchmark-results/` — місце для CSV-журналів, скопійованих із каталогу збережень LÖVE
- `fonts/` — шрифт інтерфейсу та його ліцензія

Модулі отримують посилання на спільний контекст через метод `:bind(ctx)`; це дозволяє уникати циклічних `require` між підсистемами.

## Прогресія після максимальних рангів

Коли всі 8 звичайних перків досягають своїх `maxRank` (31 ранг сумарно), нові підвищення рівня пропонують три повторювані майстерності ветерана: `Гостріша сталь` (+2 шкоди мечем), `Друге дихання` (+10 до максимального HP та лікування до 10 HP) і `Легкий крок` (+8 до швидкості). Їхні ранги не обмежені та відображаються окремо від рангів звичайних перків.

## VectorLab — візуальна діагностика векторів

Клавіша **F7** вмикає live-оверлей порівняння трьох напрямків для кожного рухомого ворога на тих самих `dx/dy`:

- **Блакитний** — тригонометричний еталон (`atan2 + cos + sin`).
- **Помаранчевий** — точне відтворення нормалізації PR #8 через `dx*dx + dy*dy`.
- **Зелений** — scale-safe нормалізація, яка тепер фактично керує рухом ворога в цій експериментальній гілці.
- **Червоний хрестик** — legacy-напрямок утратив валідну довжину.

Короткий слід показує недавню траєкторію. Для стрільців, що відступають, усі три напрямки порівнюються з урахуванням від'ємної швидкості. Панель показує середню/максимальну кутову похибку для PR #8 та scale-safe руху, похибку довжини нового одиничного вектора й кількість невалідних legacy-напрямків.

VectorLab вимкнений за замовчуванням. Відтворення старого алгоритму, додаткові тригонометричні обчислення й запис траєкторій виконуються тільки після натискання F7; у звичайному режимі legacy-порівняння не обчислюється. Натискання **F6** або відкриття мобільної панелі через сенсорну кнопку TEST автоматично вимикає VectorLab перед benchmark, щоб діагностичний overhead не потрапляв у Stage F/G результати. Це візуальний інструмент перевірки, а не GPU-профайлер; числові розходження потрібно інтерпретувати з урахуванням похибки floating point.

Клавіша **F8** відкриває окремий радіальний stress-режим і призупиняє ігрову симуляцію. Натисніть **1**, **2** або **3**, щоб перевірити відповідно 100, 500 або 1000 напрямків. Точки розподіляються методом golden-angle sampling. Набір масштабів охоплює нуль, underflow-sized, звичайні й великі величини, а також межу переповнення квадрату довжини аж до `1e308`.

У F8 порівнюються три реалізації: **блакитна** — тригонометричний еталон; **помаранчева** — оригінальна нормалізація PR #8 через `dx*dx + dy*dy`; **зелена** — scale-safe алгоритм, який спершу ділить обидві компоненти на `max(abs(dx), abs(dy))`, а потім нормалізує вже обмежені значення. **Червоний хрестик** позначає втрату напрямку старим алгоритмом. Для точного нульового вектора обидва алгоритми зберігають trig fallback; для ненульових дуже малих векторів scale-safe варіант може зберегти напрямок без underflow квадрата довжини. У цій експериментальній гілці scale-safe алгоритм уже керує рухом ворогів; F7 додатково порівнює його зі старим алгоритмом на реальному ігровому русі.

Метрики для кожного алгоритму включають кількість валідних/невалідних напрямків, overflow/fallback, середню/P95/максимальну кутову похибку, похибку компонентів і довжини одиничного вектора. Для невалідного напрямку кутова похибка залишається порожньою, а не маскується під нуль.

Після кожного прогону у каталозі збережень LÖVE створюються/доповнюються два append-only журнали v3: `vector_lab_summary_v3.csv` (один рядок на прогін із порівняльними метриками обох алгоритмів) і `vector_lab_vectors_v3.csv` (окремий рядок для кожного вектора зі статусом, напрямками та похибками обох алгоритмів). Старі журнали v1/v2 залишаються недоторканими. У консолі з'являються `SUMMARY_CSV=` і `DATA_CSV=` з повними шляхами. Ці файли не створюються у Git-репозиторії автоматично. Радіальний режим закривається клавішею **Esc/F8**; **F6** виходить із нього та відкриває benchmark-панель.

### Експеримент scale-safe руху ворогів

У гілці `work/scale-safe-enemy-movement` рухові напрямки обчислюються через `scale = max(abs(dx), abs(dy))`, масштабування компонентів і нормалізацію вже обмеженого вектора. Порогові перевірки AI, contact damage, кут прицілювання стрільців, від'ємна швидкість відступу та порядок «рух → постріл» залишені без змін. Для точного нульового або не-finite вводу збережено попередній trig fallback. Старий PR #8 алгоритм лишається тільки в F7 як діагностичний baseline й запускається лише коли оверлей увімкнений. Цей етап має бути перевірений у LÖVE 11.5 на melee/ranged поведінці та Stage G Update CPU перед будь-яким злиттям.

## Stage F — профілювання продуктивності

Необов'язкову панель тестування можна відкрити клавішею **F6**. Поки вона відкрита, звичайний ігровий цикл призупинений. Доступні контрольовані сценарії:

- **1–4** — змішані групи з 50, 200, 500 і 1000 ворогів (склад хвилі 3).
- **5** — підтримання приблизно 250 активних ворожих снарядів.
- **6** — 500 XP-сфер поза радіусом підбирання.

Кожен сценарій має 2 секунди прогріву та 10 секунд вимірювання. На час вимірювання панель намагається вимкнути VSync, щоб частота оновлення монітора не обмежувала FPS; після завершення сценарію початковий режим VSync відновлюється. Стан VSync виводиться на панелі та в консолі. Це потребує LÖVE 11.3 або новішої версії (`love.window.setVSync`); якщо функція недоступна або режим не вдалося прочитати, панель попередить і залишить поточний режим без змін. Панель і консоль LÖVE показують середній FPS, середній час кадру, P50, P95, P99, мінімальний і максимальний час кадру, кількість зразків та активних об'єктів. У CSV додаються також локальний і UTC час, ID прогону, початковий і вимірюваний VSync, джерело метрики (`love.update dt`), версія LÖVE, ОС, розмір вікна, fullscreen, кількість CPU-потоків і дані графічного renderer.

Після кожного завершеного тесту результат автоматично додається до CSV-файлу `stage_f_benchmark_results.csv` у каталозі збережень LÖVE (це **не папка Git-репозиторію**). На екрані результату натисніть **O**, щоб відкрити цю теку у Провіднику Windows, або **C**, щоб скопіювати повний шлях до CSV. У консолі також друкуються `CSV_LOG=...` (повний шлях до файлу) і `SAVE_DIR=...` (тека збережень); перед повідомленням про успіх файл перевіряється через `love.filesystem.getInfo`, а його розмір показується як `CSV_BYTES=...`. У Windows типовий батьківський каталог LÖVE — `%APPDATA%\LOVE\`, а підкаталог залежить від identity гри. У CSV зберігаються дата/час, ID і назва сценарію, режим VSync до та під час тесту, джерело метрики (`love.update dt`), версія LÖVE, ОС, розмір вікна, fullscreen, кількість логічних CPU-потоків, інформація про графічний renderer, samples, середній FPS, середній/P50/P95/P99/min/max frame time, тривалість вибірки й кількість об'єктів наприкінці тесту. Остання колонка `manual_hardware_notes` залишається порожньою для ручної моделі CPU/GPU або додаткових приміток.

Для GitHub: після завершення серії скопіюйте CSV із вказаного `CSV_LOG` шляху в репозиторій, наприклад у `benchmark-results/stage_f_benchmark_results.csv`, і тоді додайте його до коміту. Файл у каталозі збережень LÖVE сам по собі не потрапляє до Git. Після завершення натисніть **Esc**, щоб очистити тестову сцену й повернутися до нового забігу. **F6** також закриває панель.

Для порівнюваних результатів тримайте вікно гри активним, не рухайте персонажа, не перемикайтеся в інші програми під час вимірювання та запускайте кожен сценарій щонайменше тричі. Записуйте модель CPU/GPU, версію LÖVE, роздільну здатність і стан VSync разом із результатами. Профілювання має виконуватися на тій самій машині й конфігурації; не робіть висновків про потребу оптимізації за одним запуском.

## Stage G — профілювання систем гри

Stage G розширює ту саму панель **F6**, не змінюючи бойову логіку. Панель працює і на Android: у нижньому правому куті з'являється сенсорна кнопка **TEST**, а меню має великі сенсорні кнопки для шести сценаріїв. На екрані результату є сенсорні дії для відкриття теки, копіювання Stage F/Stage G шляхів, копіювання повного профільного звіту в буфер обміну (**COPY DATA**) та закриття панелі. Клавіатурні клавіші F6 і 1–6 на ПК залишаються доступними.

Під час кожного benchmark-сценарію додатково вимірюється час окремих ділянок:

- **Update:** гравець, AI/оновлення ворогів, снаряди, XP-лут і загальний Game:update.
- **Draw CPU submission:** загальне малювання та окремо лут, гравець, вороги, снаряди, HUD і benchmark overlay.

Після кожного сценарію Stage G створює окремий append-only файл stage_g_profile_results.csv у каталозі збережень LÖVE. На екрані результату натисніть **P**, щоб скопіювати його повний шлях; **O** відкриває каталог збережень. Stage F CSV і його формат залишаються окремими та незмінними.

Для кожної секції журнал зберігає середній час, P95 та максимум. Вимірювання виконуються через love.timer.getTime; збір профілю додає невеликий діагностичний overhead, тому результати Stage G треба порівнювати між собою, а не напряму зі Stage F baseline.

**Важливо:** draw_*_cpu вимірює час CPU, витрачений на подання графічних команд LÖVE, а не фактичний час виконання GPU. Ці дані допомагають знайти дорогу ділянку коду, але самі по собі не є GPU-профілем. Не робіть оптимізацій до отримання та аналізу CSV.

**Обмеження мобільного тесту:** поточне керування рухом персонажа поки використовує WASD/стрілки. Android touch UI дозволяє запускати benchmark-сценарії, але не додає віртуальний джойстик для повноцінної гри.
